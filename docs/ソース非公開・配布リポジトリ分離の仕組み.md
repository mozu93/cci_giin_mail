# ソース非公開・配布リポジトリ分離の仕組み

ソースコードは `mozu93/cci_giin_mail` を **Private** にし、利用者向けの
インストーラーだけは `mozu93/cci_giin_mail-releases` を **Public** にして配布する。

## 初回のGitHub設定

1. `mozu93/cci_giin_mail-releases` を **Public** リポジトリとして作成する。
2. GitHub の Fine-grained personal access token を作成する。
   - Resource owner: `mozu93`
   - Repository access: `cci_giin_mail-releases` のみ
   - Repository permissions: **Contents: Read and write**
3. ソースリポジトリの Actions secret に `RELEASES_REPO_TOKEN` として登録する。
4. 全端末が v1.2.3 以降になったことを確認してから、ソースリポジトリ
   `mozu93/cci_giin_mail` の Visibility を **Private** に変更する。

## リリース手順

`app/version.py` のバージョンと一致する `vX.Y.Z` タグをソースリポジトリへpushする。
GitHub Actions がテスト・ビルド後、公開配布リポジトリへインストーラーと
`CCIMail_Setup_X.Y.Z.exe.sha256` を添付したReleaseを作成する。
アプリ内の更新確認（`app/utils/updater.py` の `GITHUB_API_URL`）も
公開配布リポジトリを参照する。

## 既存ユーザーの移行

v1.2.2 以前は、ソースリポジトリ `mozu93/cci_giin_mail` を更新確認先としている。
Private に変更するとこの更新確認は匿名アクセスできなくなるため、v1.2.3 のタグだけは
旧配布先（ソースリポジトリ）にも同じインストーラーをReleaseし、既存ユーザーへ
更新通知を届ける。v1.2.3 へ更新済みのアプリは公開配布リポジトリを参照する。

移行が完了したら、`.github/workflows/release.yml` の
`Create legacy release (migration only)` ステップと `permissions: contents: write`
を削除する。

## 注意

Private リポジトリでは GitHub Actions の無料実行時間に上限がある
（Public リポジトリでは無制限）。リリース頻度が高い場合は消費量を確認すること。
