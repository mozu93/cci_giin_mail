商工会議所メール配信システム
管理者マニュアル

対象読者: 管理者権限を持つ職員 ／ 想定環境: Windows 10 / 11　社内LAN

このマニュアルについて

  • 1台のPCをデータベースサーバーとして設定し、複数の職員PCでこのシステムを共有して使えるようにする手順を説明します。
  • すでに商工会議所内で請求書発行システム（CCI請求管理システム）用のPostgreSQLサーバーを運用している場合は、同じサーバーを共用し、データベース名だけを分けることができます（第3章参照）。他システムの保守作業に巻き込まれたくない場合は、専用インスタンスを別ポートで構築することもできます（2-4参照）。
  • 本マニュアルは管理者権限を持つ職員のみ、アプリの「ヘルプ」メニューから閲覧できます。
【完成イメージ】

  サーバーPC（このマニュアルで設定）
  ├─ PostgreSQL（データベース）が常時起動
  └─ 名簿・会議・テンプレート・送信履歴を一元管理

       ↓ 社内LAN

  職員PC①　職員PC②　職員PC③
  それぞれにアプリをインストールし、初回起動時に接続設定を行うだけでOK

はじめに

このシステムでは、以下の情報が「共有データ」と「各PC個別の設定」に分かれています。

区分内容保存場所
共有データ名簿・会議・委員会・職員一覧・テンプレート・送信履歴PostgreSQLサーバー（本マニュアルで構築）
各PC個別の設定データベース接続情報、Microsoft 365設定、テスト送信先アドレス、署名各PCのローカルファイル（%APPDATA%\cci-mail\app_config.json）
個別の設定は共有DBには保存されません。アプリを配布した後、各職員のPCで個別にデータベース接続設定を入力する作業が必要です（第8章）。

第1章　サーバーPCの準備

1-1　推奨スペック

項目最低限推奨
OSWindows 10Windows 10 / 11
メモリ2GB4GB以上
ストレージ空き容量2GB5GB以上
ネットワークLAN接続（有線推奨）有線LAN

古いPCでも十分動作します。

1-2　サーバーPCのIPアドレスを固定する

職員PCから接続するために、サーバーPCのIPアドレスが変わらないよう固定します。

  1. サーバーPCで Windowsキー + R を押し、ncpa.cpl と入力して Enter
  2. 使用中のネットワークアダプター（「イーサネット」など）を右クリック →「プロパティ」
  3. 「インターネット プロトコル バージョン 4 (TCP/IPv4)」を選択 →「プロパティ」
  4. 「次のIPアドレスを使う」を選択して以下を入力
IPアドレス：    192.168.1.200　　※社内ネットワークに合わせて設定
サブネットマスク：255.255.255.0
デフォルトゲートウェイ：192.168.1.1　※ルーターのIPアドレス
優先DNSサーバー：192.168.1.1
確認方法：設定前に Windowsキー + R → cmd → ipconfig を実行すると現在のIPアドレスとゲートウェイが確認できます。

「OK」で閉じます。設定したIPアドレスをメモしておいてください。職員PC設定時に使います。

第2章　PostgreSQLのインストール

すでに商工会議所内の他システム（請求書発行システムなど）用にPostgreSQLサーバーが稼働している場合は、この章は不要です。第3章に進んでください。ただし、他システムとの同居に不安がある場合は2-4　既存のPostgreSQLと共存させる場合もあわせてご確認ください。

2-1　インストーラーのダウンロード

  1. ブラウザで https://www.postgresql.org/download/windows/ を開く
  2. 「Download the installer」をクリック
  3. 最新バージョンの「Windows x86-64」をダウンロード

2-2　インストール

  1. ダウンロードした postgresql-XX-windows-x64.exe を実行
  2. 「次へ」を押し続ける（インストール先はデフォルトのままでOK）
  3. 「Select Components」画面：PostgreSQL Server／pgAdmin 4／Stack Builder にチェックが入っていることを確認
  4. 「Password」画面：postgres ユーザーのパスワードを設定（必ずメモしてください）
  5. 「Port」画面：5432 のままでOK
  6. 「次へ」→「Install」でインストール開始（数分かかります）
  7. 完了画面で「Stack Builder」のチェックを外して「Finish」

2-3　自動起動の確認

PostgreSQLはインストール時に自動的にWindowsサービスとして登録されます。

  1. Windowsキー + R → services.msc と入力して Enter
  2. 「postgresql-x64-XX」というサービスを探す
  3. スタートアップの種類が「自動」になっていることを確認（なっていなければプロパティから「自動」に変更）

2-4　既存のPostgreSQLと共存させる場合（専用インスタンスを別ポートで構築）

第3章の方法（既存サーバーに cci_mail 用のデータベースを追加するだけ）は手軽ですが、既存サーバーは他システムと共用のため、他システムのバージョンアップ・アンインストール・設定変更（postgresql.conf／pg_hba.conf の変更、リソース競合など）に cci_mail 側が巻き込まれるリスクがあります。
管理を完全に分離したい場合は、以下の手順で cci_mail 専用のPostgreSQLインスタンスをもう一つ、別ポートでインストールしてください。1台のPC上で複数のPostgreSQLインスタンスを同時に動かすことは問題ありません。

① ポートの空き確認

サーバーPC以外のPCから、候補ポート（例：5433）が使われていないことを確認します。

Test-NetConnection -ComputerName <サーバーPCのIP> -Port 5433

TcpTestSucceeded : False であれば未使用です。

② cci_mail専用インスタンスのインストール

  1. https://www.postgresql.org/download/windows/ からインストーラーをダウンロード
  2. インストーラーを実行し、以下の項目を既存インスタンスとは別の値に指定する
項目指定する値の例
インストール先C:\PostgreSQL\17-cci_mail
データディレクトリC:\PostgreSQL\17-cci_mail\data
ポート番号5433
スーパーユーザーパスワード任意（必ずメモしてください）

コマンドラインで無人インストールする場合：

postgresql-17.x-windows-x64.exe --mode unattended ^
  --unattendedmodeui minimal ^
  --superpassword "スーパーユーザーパスワード" ^
  --serverport 5433 ^
  --prefix "C:\PostgreSQL\17-cci_mail" ^
  --datadir "C:\PostgreSQL\17-cci_mail\data" ^
  --servicename "postgresql-cci_mail" ^
  --servicepassword "スーパーユーザーパスワード"

③ データベースの作成

"C:\PostgreSQL\17-cci_mail\bin\psql.exe" -U postgres -p 5433 -c "CREATE DATABASE cci_mail;"

④ リモート接続の許可

このインスタンス専用の postgresql.conf（例：C:\PostgreSQL\17-cci_mail\data\postgresql.conf）を編集：

listen_addresses = '*'

このインスタンス専用の pg_hba.conf（例：C:\PostgreSQL\17-cci_mail\data\pg_hba.conf）に追記：

host    all             all             192.168.1.0/24          scram-sha-256
既存インスタンスの postgresql.conf／pg_hba.conf は変更しないでください。

⑤ ファイアウォールの設定

第5章の手順で、ポート番号を 5433 にして受信規則を追加します。

netsh advfirewall firewall add rule name="PostgreSQL cci_mail (5433)" dir=in action=allow protocol=TCP localport=5433

⑥ サービスの再起動

net stop postgresql-cci_mail
net start postgresql-cci_mail

⑦ 職員PCでの接続設定

第8章の手順で接続情報を入力する際、ポート番号のみ 5433 にしてください。それ以外（ホスト名・データベース名・ユーザー名・パスワード）は通常どおりです。

第3章　データベースの作成

3-1　pgAdmin 4を起動

  1. スタートメニューから「pgAdmin 4」を起動
  2. 起動時にマスターパスワードを設定するよう求められる場合は、任意のパスワードを設定
  3. 左側のツリーで「Servers」→「PostgreSQL XX」をクリック
  4. インストール時に設定したパスワードを入力して「OK」

3-2　データベースを作成

  1. 左ツリーの「Databases」を右クリック →「Create」→「Database...」
  2. 「Database」欄に cci_mail と入力
  3. 「Save」をクリック
商工会議所内で他システム（請求書発行システムの cci_billing など）と同じPostgreSQLサーバーを共用する場合は、この手順で新しいデータベース（cci_mail）だけを追加で作成すればOKです。サーバー・ユーザー・パスワードは共通で使い回せます。
ただし他システムの保守作業に巻き込まれたくない場合は、共用せずに2-4　既存のPostgreSQLと共存させる場合の手順で専用インスタンスを構築してください。

3-3　接続ユーザーの確認

デフォルトの postgres ユーザーをそのまま使用します。セキュリティを強化したい場合は専用ユーザーを作成してください（任意）。

第4章　社内の他のPCからの接続を許可する設定

セキュリティについて：この設定はあくまで社内LAN内のPCからの接続を許可するものです。インターネット（外部）からはアクセスできません。

4-1　postgresql.conf の編集

  1. エクスプローラーで C:\Program Files\PostgreSQL\XX\data\ フォルダを開く（XXはバージョン番号）
  2. postgresql.conf をメモ帳で開く
  3. listen_addresses を検索（Ctrl+F）
  4. 以下のように変更する
変更前：#listen_addresses = 'localhost'
変更後：listen_addresses = '*'

上書き保存します。

メモ帳で保存できない場合：ファイルをデスクトップにコピー → 編集 → 元のフォルダに戻す

4-2　pg_hba.conf の編集

同じフォルダの pg_hba.conf をメモ帳で開き、ファイルの末尾に以下の1行を追加します。

host    all             all             192.168.1.0/24          md5
192.168.1.0/24 は社内ネットワークのアドレス帯です。ルーターのアドレスが 192.168.0.1 の場合は 192.168.0.0/24 に変更してください。すでに他システム用にこの行を追加済みの場合は、そのまま流用でき、この手順は不要です。

保存して閉じます。

4-3　PostgreSQLを再起動

  1. Windowsキー + R → services.msc を開く
  2. 「postgresql-x64-XX」を右クリック →「再起動」

第5章　Windowsファイアウォールの設定

社内の他のPCからアクセスできるよう、ポート5432を開放します。すでに他システム用に設定済みの場合はこの章は不要です。

5-1　受信規則の追加

  1. スタートメニューで「Windows Defender ファイアウォール」を検索して開く
  2. 左側の「詳細設定」をクリック
  3. 左ツリーの「受信の規則」を右クリック →「新しい規則」
  4. 「ポート」を選択 →「次へ」
  5. 「TCP」を選択、「特定のローカルポート」に 5432 と入力 →「次へ」
  6. 「接続を許可する」→「次へ」
  7. 「ドメイン」「プライベート」にチェック（「パブリック」は外してOK）→「次へ」
  8. 名前に PostgreSQL と入力 →「完了」

5-2　設定の確認（サーバーPC上で実行）

  1. サーバーPCでスタートメニューを右クリック →「Windows PowerShell」を開く
  2. 以下のコマンドを入力して Enter
Test-NetConnection -ComputerName localhost -Port 5432

TcpTestSucceeded : True と表示されればOKです。

5-3　職員PCから接続確認

  1. 職員PCでPowerShellを開く
  2. 以下のコマンドを入力（IPアドレスはサーバーPCの実際のものに変更）
Test-NetConnection -ComputerName 192.168.1.200 -Port 5432

TcpTestSucceeded : True と表示されればOK。False の場合は第5章-1の手順を再確認してください。

5-4　ウイルス対策ソフトの確認

ウイルス対策ソフト（ウイルスバスター、ESET、Norton 等）を導入している場合、そちらのファイアウォール機能が別途ポートをブロックしている場合があります。

確認方法：第5章-3の確認で False になる場合、ウイルス対策ソフトを一時的に無効にして再テストする。それで True になればウイルス対策ソフト側の設定が原因です。各ソフトの設定で「ポート5432を許可」するルールを追加してください。

第6章　Windowsアップデートの設定

業務時間中に突然再起動されないよう設定します。

  1. Windowsキー + I で設定を開く
  2. 「Windows Update」→「詳細オプション」→「アクティブ時間」
  3. 業務時間（例：8:00〜18:00）を設定する

これにより、業務時間外にのみアップデートの再起動が行われます。

第7章　Microsoft 365 の設定

メール送信には、Microsoft 365（Azure AD）のアプリ登録が必要です。これはPostgreSQLとは別の、メール送信専用の設定です。

7-1　Azure ADにアプリを登録する

  1. https://portal.azure.com にアクセスし、管理者権限のあるMicrosoft 365アカウントでログイン
  2. 「Azure Active Directory」→「アプリの登録」→「新規登録」
  3. 名前に「商工会議所メール配信システム」などわかりやすい名前を入力
  4. 「サポートされているアカウントの種類」は「この組織ディレクトリのみに含まれるアカウント」を選択
  5. 「リダイレクトURI」は「パブリック クライアント/ネイティブ」を選び、http://localhost を入力
  6. 「登録」をクリック

7-2　APIのアクセス許可を設定

  1. 登録したアプリの画面で「APIのアクセス許可」を開く
  2. 「アクセス許可の追加」→「Microsoft Graph」→「委任されたアクセス許可」
  3. Mail.Send を検索してチェックし追加
  4. 組織の管理者である場合は「管理者の同意を与えます」をクリック

7-3　テナントID・クライアントIDを控える

アプリの「概要」画面に表示される以下の2つの値を控えます。

項目説明
アプリケーション (クライアント) ID各職員PCの設定画面「Microsoft 365」タブの「クライアントID」に入力
ディレクトリ (テナント) ID同「テナントID」に入力
これらのID自体はパスワードのような秘密情報ではありませんが、社外に不用意に公開する必要はありません。各職員PCの設定はローカルファイルに保存され、共有DBには保存されません。

7-4　各職員の初回送信時の認証

各職員のPCで初めてメールを送信しようとすると、ブラウザでMicrosoft 365のログイン画面が表示されます。ここで職員自身のMicrosoft 365アカウントでログインすると、以後はそのアカウント本人としてメールが送信されます（2回目以降は自動的にログイン済み扱いになります）。

第8章　職員PCへのアプリ設定

サーバーとMicrosoft 365の設定が完了したら、各職員PCでアプリを起動して接続設定を行います。

8-1　アプリの初回起動

  1. GitHubのリリースページ（https://github.com/mozu93/cci_giin_mail/releases）からインストーラーをダウンロードして実行する
  2. アプリを起動すると「初期設定」ウィザードが自動的に表示される

8-2　接続情報の入力

項目入力値
DB種別PostgreSQL（複数人共有） を選択
ホストサーバーPCのIPアドレス（例：192.168.1.200）
ポート5432
データベース名cci_mail
ユーザー名postgres
パスワードインストール時に設定したパスワード

8-3　接続テスト

「接続テスト」ボタンをクリックし、「接続に成功しました。」と表示されればOKです。「保存して開始」をクリックしてアプリを使い始めます。

8-4　Microsoft 365の設定

ログイン後、「設定」タブ →「Microsoft 365」で、第7章で控えたテナントID・クライアントIDを入力します。テスト送信先アドレスも、この画面で職員ごとに個別に設定します（自分宛てのアドレスを設定するのがおすすめです）。

DB接続設定を後から変更したい場合は、「設定」タブ →「データベース接続」から可能ですが、変更を反映するにはアプリの再起動が必要です。

第9章　職員・権限管理

「設定」タブの「職員管理」は、管理者権限を持つ職員にのみ表示されます。

9-1　最初の管理者

まだ誰も職員登録されていない状態で、ログイン画面から最初に登録した職員が、自動的に管理者になります。

9-2　職員の追加

  1. 「設定」タブ →「職員管理」を開く
  2. 職員名を入力し、必要に応じて「管理者にする」にチェックを入れて「追加」

9-3　管理者権限の付与・剥奪

一覧から職員を選択し「管理者権限 切替」ボタンで、管理者/非管理者を切り替えられます。

最後の1人の管理者を非管理者にしようとすると、確認の警告が表示されます。管理者が0人になると、以後は誰も職員管理タブにアクセスできなくなり、UI上での復旧手段がありません（職員を全員無効化してログイン画面から登録し直すか、データベースを直接操作する必要があります）。操作は慎重に行ってください。

9-4　職員の有効/無効

退職・異動した職員は削除ではなく「有効/無効切り替え」で無効化することを推奨します（送信履歴等の過去データとの整合性を保つため）。無効化された職員はログイン画面の選択肢から除外されます。

トラブルシューティング

接続できない場合のチェックリスト

  • ☐ サーバーPCの電源が入っているか
  • ☐ サーバーPCとLANで同じネットワークに接続されているか
  • ☐ services.msc でPostgreSQLサービスが「実行中」になっているか
  • ☐ ファイアウォールでポート5432が開放されているか（第5章）
  • ☐ pg_hba.conf のネットワークアドレス帯が正しいか（第4章）
  • ☐ postgresql.conf の listen_addresses = '*' になっているか（第4章）
  • ☐ PostgreSQLを再起動したか（第4章-3）

サーバーPCを再起動した後につながらない

通常は自動復旧しますが、30秒〜1分ほど待ってから職員PCでアプリを再起動してみてください。

メール送信でエラーが出る

  • 「設定」タブのMicrosoft 365設定（テナントID・クライアントID）が正しいか確認してください（第7章）。
  • 職員本人のMicrosoft 365アカウントの認証が切れている可能性があります。一度アプリを再起動し、再度サインインを求められたら実行してください。
  • Azure ADのアプリ登録で「APIのアクセス許可」にMail.Sendが正しく設定・同意されているか確認してください（第7章-2）。

このマニュアルは商工会議所メール配信システム専用です。同一サーバーで請求書発行システム（CCI請求管理システム）を併用している場合、第1〜6章のサーバー設定は共通の作業として一度行えば両システムで使い回せます。
